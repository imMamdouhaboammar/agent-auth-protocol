AgentAuth Protocol

AgentAuth is an open system design for AI agent identity, authentication, authorization, delegation, federation, runtime attestation, and native “Login as Agent”.

It defines how a target service can know that an AI agent is acting, identify the durable Agent Principal and current Agent Instance, preserve the represented human or organization, verify scoped delegated authority, and keep the resulting action attributable and auditable.

View the canonical repository · Read the normative protocol core · How to cite AgentAuth

What does AgentAuth solve?

OAuth clients, service accounts, workloads, and browser sessions do not automatically express the full identity of an AI agent. AgentAuth separates the represented Subject, the AI Agent Actor, the running Agent Instance, the Delegation Grant, proof-of-possession, Provider policy, and the final Agent-aware session.

Subject        = represented human / organization / workload / Agent
Agent Actor    = durable AI Agent Principal
Agent Instance = current runtime with its own proof key
Grant          = explicit scoped delegated authority
Provider       = final local authorization authority

What is Login as Agent?

Login as Agent is a native authentication flow in which the target intentionally accepts an AI Agent Actor and preserves that fact in its server-side authorization and session state. It is not a bot typing a human password, a special User-Agent string, or an ordinary OAuth client identifier.

Core design areas

Identity
Agent Principal, Agent Instance, represented Subject, issuer-qualified identity.
Authentication
Proof-bound credentials, DPoP or mTLS, native Agent sessions.
Authorization
Capabilities, deterministic constraints, Provider policy, progressive consent.
Delegation
Subject/Actor separation and child authority that can only attenuate.
Federation
Explicit directional trust, direct or brokered Provider trust, no hidden transitivity.
Attestation
Runtime evidence as a trust input, never as an automatic permission grant.

Standards-first

AgentAuth composes existing standards rather than replacing them. The design reuses OAuth, OpenID Connect, Token Exchange, DPoP, mTLS, Rich Authorization Requests, Protected Resource Metadata, RATS, EAT, and SPIFFE concepts where they already solve the lower-level security problem.
